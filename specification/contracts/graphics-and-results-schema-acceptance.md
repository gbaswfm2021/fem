# Graphics and results schema acceptance

Pass this schema acceptance gate before freezing a candidate. Verify both the saved, reopened schema and its behavior in the registered Model Editor on canonical, disposable model files in the Codex in-app browser. Use small inputs authored solely from the [Model 2 contract](../../docs/fullmeta-model-2.md) and deterministic renderer data to exercise those declarations through the registered package. Complete the separate [project-level tree command gate](tree-context-menu-contract.md#project-level-command-gate) before freeze. Existing project JSON, its artifacts, and observations from it are outside acceptance.

## Evidence for each check

1. Save the schema through the designer, reopen it, and validate the effective declarations. Record the schema identity, profile, JSON Pointer, ordered rule or widget, resolved scene and input bindings, and registered handler or renderer. Record that the selected item resolves to its own Settings path.
2. Exercise the declaration with an authored model and the registered package. Record the triggering path and type, exact expected and actual visible state, the run or renderer input identity, and the outcome. Verify the serialized model after any Settings edit. Include a missing-data or other negative control where the check names one.
3. Run the declaration checks on the reopened schema. Use `graphicsConsoleIssues` with the registered widget IDs, `graphicsSceneForSelection` for rule precedence, `graphicsSceneInputs` for each binding, `graphicsFocusTargets` for stable target IDs, and `graphicsWidgetForLayer` for the dimension-specific field widget. Verify handlers and `onSelect` against the effective package registrations. A declaration that validates but resolves a wrong scene, missing input, wrong target, or incorrect visible effect fails the corresponding check. [Shared Graphics Console contract](../../../../platform/ui/widgets/graphics-console/README.md)

Deterministic artifacts can exercise projection and rendering without a numerical solve. Exercise the same scene and Settings bindings through the checked result route with generated disposable output for the 2D wave, 3D wave, and stationary cases. Use schema-derived inputs and verified outputs for both levels. Record blocked designer or runtime capabilities with a reproduction. [Designer workflow](designer-authoring.md) · [Runtime result contract](../RUNTIME.md#results-resolution-and-plots)

Create an evidence row for every GX ID below. For a multi-step sequence, record each step's visible outcome before moving to the next one. A row can share inputs or screenshots with other rows when the evidence identifies the specific assertion. For asynchronous cases, record which request was held, what the user selected or changed before it completed, and the settled result after release. For canvas checks, keep the viewport, device scale, and camera fixed during a comparison and pair the visible view with the draw evidence required by the case.

## Scene, selection, and control checks

Inspect `x-fullmeta-ui-tree`, `x-fullmeta-ui-graphicsConsole`, and the effective `x-fullmeta-ui-modelEditor` together.

| Check | Saved declaration and input | Required visible outcome |
| --- | --- | --- |
| GX-01 Default and precedence | `defaultScene` is `structure`. Check ordered `rules` on a model root, definition link, mesh, Study, result collection, field item, and both `sweep` and `plot.sweep` items. | Selecting a structural item opens Geometry and that item's Settings. Selecting a field opens 2D plot or 3D plot by dimension. A sweep opens 1D plot in Plot view. A click on a definition link from either result scene returns to Geometry and opens the correct definition table. |
| GX-02 Nested geometry focus | Select a union or intersection and then one of its child features. Exercise the geometry rule and its feature focus target by ID. In 3D, include a thin attached box so its thickness is smaller than a typical preview sampling interval. | Each row opens its own Settings. The group shows its composed boundary and exact extent. Selecting the child reveals its own accent outline. A top-level view preserves thin features and omits internal tessellation edges. |
| GX-03 Selection and references | Check named selection, `selectionId`, `periodicPairId`, and the periodic pair's two boundary endpoint references. Include an outer region with an excluded interior, a boundary reference, and a filter that resolves to nothing. On a unit rectangle, use a boundary filter `x-sign(0)` and the declared `signedOne` real policy. | Each row opens its own Settings. A domain highlight excludes the cutout. Boundary, edge, and point selections highlight the corresponding entity rather than its enclosing primitive. A pair or periodic condition highlights both boundaries. An empty selection shows a no-match message. The filtered boundary highlights x = 1, not x = 0, in the CAD preview and after reopening. The mesher resolves the same boundary. |
| GX-04 Data, defaults, and persistence | Verify `structure` and `field` resolve the same control identities `geometry`, `mesh`, `edges`, with defaults on/off/on and `edges.requiresVisible: ["mesh"]`. Bind Geometry to the model, Mesh and Edges to the checked mesh, and the field surface to the resolved field input. | Run the checkbox sequence below. Check the actual canvas, checkbox values, and selected Settings path after each step. The field surface has no toolbar checkbox. |
| GX-05 Mesh transition | Verify `previewLayerRole: "mesh"`, the preview route, and artifact eligibility. Test a successful Build Mesh, an initial restore, a stale mesh, and an artificially delayed restore that completes after a user preference change and a scene switch. | Build Mesh enables Mesh after verification. Initial restore enables Mesh if untouched. Neither changes Geometry, Edges, selection, Settings, or camera. The delayed response does not overwrite the user's Mesh choice or the active scene. A stale mesh never renders. |
| GX-06 Shared viewport | Verify the layered surface, profile layout defaults, orientation presentation, and Reset view registration in 2D and 3D. Start in Geometry, pan or rotate and zoom, select a field, switch to Plot or Table when applicable, and return. | Model and field share orientation, zoom, and pan. The lower-right axis guide follows the projection. A stationary click on the canvas leaves selection and Settings in place. Reset restores the default camera and centered fit while retaining the selected row, layer choices, and splitter positions. |
| GX-07 Result selection and load order | Verify `onSelect: "loadResult"`, the selected item binding, field data input, and Plot and Table input. Start a result load and select another item before the response. Use deterministic field artifacts with omitted dimension, contradictory dimension, invalid connectivity, and missing data. | The late response cannot replace the current view. Normalize an omitted dimension only from unambiguous topology. Missing or malformed data produces a settled, actionable state with the artifact path and precise reason. Selecting a checked result exposes that result's source, appropriate controls, and data. |

Use a spec-derived disposable model with a definition, at least two feature and selection IDs, a material, a mesh-size control, a periodic pair and condition where the profile supports them, a Study, and result recipes. [Model tree contract](../UI.md) · [Graphics declaration and controls](application-ui-javascript-contract.md#graphics-declaration-and-controls)

For GX-04, record controls in Geometry/Mesh/Edges order. With geometry and no eligible mesh, a fresh model starts `on/off/on`; Mesh and Edges are disabled and explain why. Restore a matching mesh on first open without touching Mesh and expect `on/on/on`. Then use this sequence with checked inputs:

| Action | Checked state | Visible result |
| --- | --- | --- |
| Turn Mesh off | on/off/on | Only CAD outlines remain among the three layers. |
| Turn Edges off with Mesh off | on/off/off | Edges is enabled because mesh data exists. Canvas content is unchanged. |
| Turn Mesh on | on/on/off | Filled mesh faces return without wires. |
| Turn Edges on | on/on/on | Wires appear over the mesh faces. CAD outlines and faces remain. |
| Turn Geometry off | off/on/on | CAD outlines disappear; mesh faces and wires remain. |
| Turn Edges off | off/on/off | Wires disappear; mesh faces remain. |
| Select a checked field, a structural item, and a sweep; switch Plot → Table, then return to the field | off/on/off in each layered scene | The field surface is drawn with faces, without CAD or wires. Plot/Table hides the three controls. Each tree click opens its own Settings and each tab or layer click leaves it selected. |

Run one repeat with a different canonical model; its preferences start from its own defaults and checked initial data. For a checked artifact that lacks mesh wires, verify the disabled reason and no wire pixels while the field remains visible. Compare layer effects on a settled canvas with fixed viewport and camera; checkbox state alone does not pass GX-04.

## Field results and Settings checks

| Check | Saved declaration and input | Required outcome |
| --- | --- | --- |
| GX-08 Result fields | Inspect the effective **Domain field plot** Settings branch, one combined Quantity control where editable, and one fixed saved-case selector bound to the filters path. Exercise a 2D wave field, a 3D wave field, and a stationary temperature field. Seed a zero-in-dimension component that actually has a stored array, a pointwise definition, and an eligible quantity without samples. | Quantity options follow the shared widget order, omit zero and nonplottable quantities, and disable eligible options lacking data. Quantity changes redraw from the same checked artifact without requesting another case or resetting the camera. A saved-case change updates only filter coordinates and preserves the frequency expression and unit. A stationary result shows K and no frequency control. | GX-09 Checked source | Use a field artifact with known node and cell counts, run and Study IDs, case coordinates, and optional solver and residual metadata. The canvas title and summary identify the view, recipe, and resolved case. Missing optional metadata is omitted or reported unavailable. |
| GX-10 3D polygon and coordinate transform | Bind the field layer to a tetrahedron with model vertices `(0,0,0)`, `(0,1,0)`, `(2,0,0)`, and `(2,0,1)` in metres and scalar `x + 2y + 3z`. Cut at `x = 1000 mm`. Repeat with solver coordinate order `[y,z,x]` and a declared nonzero origin that maps back to those vertices. | The x cut is a complete quadrilateral rendered as two triangles. Its corners are at y/z pairs `(0,0)`, `(0.5,0)`, `(0.5,0.5)`, and `(0,0.5)`, with scalar values 1, 2, 3.5, and 2.5. The permuted and translated artifact yields the same model geometry. Check the y and z defaults, an out-of-bounds edit, and saved expression and unit after reopening. |
| GX-11 Range and palette | Exercise magnitude and real or imaginary parts using finite triangle-corner occurrences. Use an occurrence list sorted from 0 through 200, a repeated shared corner with unequal valence, and a constant real field of 5 in its displayed unit. | The computed magnitude range is 0–197 and the real or imaginary range is 4–196 for that list. With an unequal-valence mesh, verify the percentiles against the expanded corner occurrences, not a deduplicated vertex list. The constant real field spans 5–6. The plot and vertical colorbar use the same palette and range and show the quantity and unit. |

Check the schema's widget bindings and profile overrides against the [shared widget contract](shared-widget-contract.md). Verify the field projections against the [surface and color rules](../RUNTIME.md#field-surfaces-and-color-scale).

## Sweep results and Settings checks

| Check | Saved declaration and input | Required outcome |
| --- | --- | --- |
| GX-12 Study series and table | Use a Study-backed plot with two independent sampled coordinates and a global symbol whose checked table stores only `_re` and `_im` columns. Inspect the effective dataset slice widget, series selector, mirrored `tableColumns`, and Plot and Table bindings. | Choose the x-axis, a fixed coordinate, and the global symbol. Plot and Table use the same checked rows. Table shows x, fixed coordinates, and values in that order. The default real series label is `Re(symbol)`, with its unit where applicable. The saved recipe keeps its symbol key and ordered value columns. |
| GX-13 Apply and units | Change the selected x-axis, fixed coordinate, or series on a loaded plot and Apply. Add a dataset with a compatible different display unit, and try an incompatible unit in a separate check. Use a file-backed dataset with a literal `frequency_kHz` header, samples 0.3 and 0.35, and `source.columnUnits.frequency_kHz: "kHz"`. Change its `xUnit` from `kHz` to `Hz`. Include an unmapped literal-header control. | The active views reflect the applied recipe and verified data without a new solve. Compatible axis units convert to a common unit. An incompatible axis reports the dataset and column. File-backed columns retain literal keys. The mapped file shows 300 and 350 Hz immediately after Apply and again after Save and reopen. Verify the saved recipe changes only `xUnit`. The unmapped control applies the same legacy interpretation immediately and after reopening. |
| GX-14 Export | Inspect the registered save-figure route and the Plot/Table action availability. Exercise ready, partially ready, and active Study states, and the declared PNG, SVG, and PDF formats. | Export is available in Plot when all datasets are ready. Before freeze, keep evidence for each GX and project-level command check with the schema, package, and shared host identities. Record the actual browser outcome and saved/reopened values for persisted edits. Both deterministic and live checks are required where specified. A blocked or unobserved required interaction keeps the gate open. Use the [UI coverage method](function-contract-coverage-method.md#settings-and-renderer-coverage) to verify fields and interaction outcomes beneath each selected row.
