# FEM shared-widget bindings

The Schema Editor authoring tools set the widget, data binding, choices, labels, visibility, and actions. The Model Editor uses those declarations through the shared widgets. target application supplies model-specific data and semantics through its schema and documented package interfaces. The widget catalog and the model UI inventory define the available bindings and project paths. [Shared widget catalog](../../../../platform/ui/widgets/catalog.json) · [Model and UI functions](../UI.md)

Author field behavior in `x-fullmeta-ui-behavior` using `format` `fullmeta-ui-behavior/1`, target kind `field`, and context `projectEditing`. The widget assignment is `payload.widget.type` with its `settings`. Put field display labels, visibility, and icons in the supported presentation controls. [Shared UI behavior declaration contract](../../../../platform/ui/schemas/fullmeta-ui-behavior-1.schema.json)

## Tree and Settings tables

Shared widget presentation uses the supplied React + JSX implementation while schema annotation meanings, widget IDs, source/model paths and draft transactions remain the contract above. Schema authors continue selecting/configuring shared widgets; they do not create JSX for each field. New application-specific visual components use compiled JSX behind the documented package/provider interfaces and a registered public `widget.js` when a new widget is required. Reuse the shared tree, Settings, dialog and graphics controls rather than copying them into the application. See [Public provider and lifecycle contract](../../../../platform/docs/frontend-provider-contract.md).

Use the shared Tree for project navigation. Bind root sections and their roles through `x-fullmeta-ui-tree`. Use its child collection role for nested geometry features and named periodic pairs. A disclosure handle expands the selected parent's children. Clicking the item label selects its actual project path and opens its own Settings. Present permitted add, rename, duplicate, delete, and order actions on the owning item or collection. Preserve the item's stable ID during rename and reorder. Use the declared creation template and a unique ID on add or duplicate. Update selection to a surviving item or its owning section on removal. [Tree declaration contract](../../../../platform/ui/widgets/tree/fullmeta-ui-tree-1.schema.json)

Declare Physics as a top-level `objectRoot` at `/model/physics`. Its **Physics** label selects the interface and the disclosure on that same row reveals its `objectEntries` conditions. Each named condition uses its own immediate child row and actual object-member path. Use the model UI title declaration for the **Physics** Settings heading and the condition type headings. The tree uses the stored name on the condition row. [Tree and Settings inventory](../UI.md#canonical-tree-item-inventory)

Definitions is a presentation group with three `collectionLink` declarations. Each uses the collection key and its actual model path. Declare the corresponding `definitionCollections` entries and roles under `x-fullmeta-ui-modelEditor`. Expose the effective declaration as `modelEditorUi` from the package. Selecting a link opens the shared Model Editor definition table for that array. The count is the number of stored entries, including zero. [Model Editor behavior contract](../../../../platform/ui/widgets/model-editor-behavior/fullmeta-ui-model-editor-1.schema.json)

| Collection key | Model path | Symbol role | Settings columns in order | Add action |
| --- | --- | --- | --- | --- |
| `parameters` | `/model/parameters` | `parameter` | Symbol, Expression, Unit, Value, Description, Actions | Add parameter |
| `variables` | `/model/variables` | `globalVariable` | Symbol, Expression, Unit, Description, Actions | Add global variable |
| `pointwiseVariables` | `/model/pointwiseVariables` | `pointwiseVariable` | Symbol, Expression, Unit, Description, Actions | Add pointwise variable |

Each table row edits the stored `symbol`, `expression`, `unit`, and `description` for one record in array order. Unit is a selector with the declared unit choices. Parameters enable `showResolvedValue`. Evaluate their expressions with the model's parameter environment and display the read-only Value in the declared unit. For an unresolved value show an unavailable value and its diagnostic. Global and pointwise expressions use their declared evaluation scopes. The pointwise scope includes coordinates and the scenario's field symbols. The global scope supports the declared integration operators and observables.

Set `tableLabel` to Global parameters, Global variables, or Pointwise variables. Use `emptyLabel` parameters, global variables, or pointwise variables and `addLabel` parameter, global variable, or pointwise variable. Parameters use `reservedSymbols: "parameter"` and `invalidatePreview: true`. The variable collections use `reservedSymbols: "expression"`. Parameter edits invalidate an existing preview for the changed geometry inputs.

Give row controls an accessible label that identifies the record. Use the shared add, move up, move down, and delete actions. Disable moves at the applicable end of the array. Commit a valid field edit when the user leaves the field and persist it on Save. Validate symbol syntax, reserved names, and uniqueness across the three collections. A valid symbol rename updates its dependent references through the shared rename operation. A rejected rename leaves the prior symbol and references intact and shows its reason. Save and reopen preserves all record values, optional members, and order except for the user's edits. The computed Value stays in the view.

On Add, use the first unused numbered symbol with prefix `p` for Parameters, `v` for Global variables, or `u` for Pointwise variables, starting at 1 across the shared symbol namespace. Give the record a fresh ID and set `name` to its symbol, `unit` to `"1"`, and `description` to the empty string. Start a parameter's `expression` at `"1"` and a variable's at `"0"`.

## Keyed Choice Matrix for selections

Bind the shared `keyedChoiceMatrix` widget to `/model/selections/*/addresses`. It is part of the Settings for the selected named selection. Configure `choiceSource` with `scope` `model` and path `geometry`, `features`. Use `id` for `choiceKeyProperty`, `{name}` for `choiceLabelTemplate`, and `membership` for `valueMapProperty`. The choices represent addressable geometry features. Use `outside` as `omittedValue`, and show `Outside`, `Inside`, and `On boundary` for the tokens `outside`, `inside`, and `boundary`. Apply the selection entity's membership choices and constraints. For example, a domain address offers Outside and Inside. An address that selects a boundary must include at least one eligible On boundary membership. [Keyed Choice Matrix contract](../../../../platform/ui/widgets/keyed-choice-matrix/fullmeta-ui-keyedChoiceMatrix-1.schema.json)

Use a choice-source `schemaFilter` with annotation keys `x-fullmeta-geometryDimensions` and `x-fullmeta-geometryDimension`, and value path `scenario`, `dimension`. Set `choiceSetProperty` to `entity`. Domain offers `outside` and `inside`. Boundary, edge, and point also offer `boundary`. Initialize the first row with an eligible feature Inside for domain or On boundary for the other entities. Set `candidateLimit` to 100,000. Display `Address {row}: {label}` for the cell's accessibility label and `Remove address {index}` for removal. Explain the address union and the membership codes `0`, `1`, and `*`. A missing ID uses `Missing geometry feature · {key}`.

Each stored address is one group labeled `Address {index}` with a one-based index. Within it, each feature is named and has its own membership control. An omitted feature key displays Outside. An edit to Outside removes the key, and an edit to Inside or On boundary stores the corresponding token under that feature ID. Show a stored missing feature ID with a diagnostic so it can be repaired. Keep any existing values and address order on open. `Add address` adds one row through the widget's distinct-row action, `Remove address` removes the chosen row within the declared minimum, and ordering controls move that exact row where enabled. Show a reason when there is no eligible feature or unused choice. Display the selection's resolved entity set in Graphics and apply its coordinate expression as a filter over the union of its address rows. Address details appear only inside Settings.

## Field and result widget bindings

Use the following bindings for the corresponding supported field variants. A concrete model field retains its declared JSON representation and uses its schema titles, allowed values, unit groups, and visibility conditions. Apply a choice to its bound field and update dependent Settings and graphics through the same selected model path.

| Field or view | Shared widget | Required interaction and stored value |
| --- | --- | --- |
| IDs, names, entity and position modes, enum choices, boolean options, and scalar text | Value Control (`valueControl`) | Display stable automatic IDs and type tokens as read-only. Edit names and expressions as text. Show enum choices and boolean checkboxes. Offer only choices allowed by the selected field variant. Store the declared scalar type. |
| Geometry tolerance and radii, mesh bounds and local sizes, material quantities, Physics frequency and boundary quantities, and result frequency or explicit cut coordinate | Quantity (`quantity`) | Show an expression entry and its declared unit control. Use compatible units for the quantity and keep the stored `expression` and `unit` pair. Use a read-only unit display where the effective widget declares it. A single allowed choice can still appear in a selector. |
| Geometry position, size, center and other supported coordinate vectors, periodic translation, incident polarization, and phase vector | Quantity Vector (`quantityVector`) | Show each component with a meaningful axis or field-component label and its expression and unit. Use x and y for 2D coordinate fields and x, y, and z for 3D coordinate fields. Preserve the declared component count and ordered quantity objects. |
| Selection, periodic pair, and other declared model references | Reference Selector (`referenceSelector`) | Show eligible referenced names from the declared path and scope. Store the stable reference ID or ordered ID list. Keep an unavailable saved reference visible with its diagnostic. Filter domain and boundary choices by the consumer's entity and enabled-pair requirements. |
| Study discretization | Related Fields (`relatedFields`) | Present element order and formulation together for the selected Study. Derive the choices from the linked Physics and solver capabilities. Persist the individual `discretization` members. |
| `/model/study/*/parameterSweep/parameters` | Scan Table (`scanTable`) and Scan (`scan`) | One ordered row per swept symbol. Select an existing parameter and use the declared range or explicit-values editor. Show Start, End, and Count for a linear range and ordered quantity entries for explicit values. Pair each expression with its own unit label. Preserve each row's `parameter` and `values` shape, units, and order. [Quantity display rule](settings-control-contract.md#quantity-values-and-display-units) |
| Field result filters and sweep dataset coordinates | Tabular Slice Selector (`tabularSliceSelector`) | Show **Data selection** with exact saved sample choices. Use fixed selection for one field case and slice selection for one sweep plot/table view. |
| Study-backed sweep series | Repeatable Choice Table (`repeatableChoiceTable`) | Show **Global variables to plot** with one ordered row per selected symbol. Mirror the selected columns into the recipe's `tableColumns`. |
| Model geometry, mesh, and field overlays | Graphics Console, shared scene or field renderer, and Selection Highlight | Resolve the scene from the selected tree path and result type. Feed verified layer data and the open model's shared visibility preferences to the console. A change of layer visibility leaves the current tree path and Settings active. |
| One-dimensional sweep result | Plot 1D and Table in the shared Plot Table view | Use the same resolved rows, independent axis, and declared series for Plot and Table. Display units and legend. Keep saved recipe keys through artifact column resolution. |

Use `x-position`, `y-position`, and `z-position` for position labels in the active dimension and the corresponding axis labels for size and center. The Related Fields declaration includes sibling `solver` with label Solver options. Scan Table uses Add parameter and Remove.

For explicit Scan values, set `labels.valueAriaLabelTemplate` to `{parameter} {value} {index} in {unit}`. The shared widget supplies the entry's unit as `{unit}`. For linear Scan values, the shared renderer takes the unit for each adjacent label and accessible name from that endpoint's own quantity. `sourceUnitProperty` identifies a unit on the swept parameter for initialization and fallback. It supplies neither a display conversion nor a replacement label for a stored endpoint. The explicit-value name template applies only to explicit values. [Scan declaration](../../../../platform/ui/widgets/scan/fullmeta-ui-scan-1.schema.json) · [Sweep unit checks](settings-control-contract.md#sweep-unit-checks)

Initialize Geometry, Mesh, and Edges from their declared visibility defaults when opening a model. Keep the preferences across structure and field scenes and while visiting the plot or table. Preserve the Edges preference as a separate checkbox value. With verified mesh data available, the Edges control remains enabled while Mesh is unchecked. Mesh faces draw when Mesh is checked. Mesh wires draw when both Mesh and Edges are checked. Disable a control with a reason when its bound data is unavailable. [Graphics declarations and controls](application-ui-javascript-contract.md#graphics-declaration-and-controls)

### Ordinary condition Settings

Apply these declarations to each effective Dirichlet, Neumann, and Impedance variant at `/model/physics/<condition-key>`. Preserve the stable condition key and show the stored name in the tree.

| Field | Effective declaration and observable control |
| --- | --- |
| `enabled` | Keep the optional boolean with effective default `true`. Leave `payload.presentation.showDefault` absent or false. Show the `enabled` checkbox before the ID when the property is stored. Use the effective value for the tree and its **Enable item** or **Disable item** action. |
| `id`, `name` | Use the titles `id` and `name` and the shared Value Control. Show **id (automatic)** as read-only and **name** as editable. |
| `selectionId` | Use title `boundary selection` and widget `referenceSelector`. Set `payload.presentation.emptyChoiceLabel` to `Choose boundary selection…`. Resolve IDs against `/model/selections` with a `targetSchema` that requires `entity` equal to `boundary`. Display the eligible selection's name and store its stable ID. Preserve an unavailable saved ID and expose its diagnostic. |
| `value` | Use title `value` and widget `quantity` for the prescribed Dirichlet or Neumann expression and its profile's unit control. |
| `impedance` | Use title `Impedance` and widget `quantity`. Leave `unitReadOnly` absent or false so the expression textbox and compatible unit selector are separate controls even with one allowed unit. |
| `incidentField` | Use title `Incident factor` and widget `quantity` with a dimensionless unit `1`. Set `optionalToggleLabel` to `Specify an incident field`, and include `polarization` in `createWithProperties` and `clearWithProperties`. Leave the absent field as the unchecked optional control until activated. Activation initializes both optional fields from the effective defaults. Show the factor expression with read-only unit `1` after activation. |
| `polarization` | Use group title `polarization` and widget `quantityVector` with `unitReadOnly: true`. Bind component labels, units, and order to the active formulation's primary field variables. The single-component formulations use **p**, **Ez**, or **Hz** as applicable. The electric formulation uses **Ex**, **Ey**, **Ez**, in that order. Use matching `componentLabels` on the effective variant, or bind `componentSource` to `primaryFieldVariables` and resolve the same ordered descriptors through the package's `quantityVectorComponents` interface. Keep the ordered stored quantity objects. |

For Impedance, open a spec-derived case with neither optional incident value. Check the exact **Specify an incident field** label and verify that Save and reopen without edits leaves both properties absent. Activate the control and verify the **Incident factor**, component labels and units, and applicable initial values. Edit an expression and Save and reopen. Compare the saved JSON to verify the expected incident factor and ordered polarization quantities, with the selection, impedance, and stable condition identity preserved. Repeat in the supported single-component and three-component formulations. An explicit clear of the incident payload removes both properties together.

### Periodic condition Settings

Apply the declarations below to the effective `periodicCondition` variant at `/model/physics/<condition-key>`. The Settings heading is **Periodic condition**. The tree label remains the stored condition name.

| Field | Effective declaration and observable control |
| --- | --- |
| `enabled` | Keep the optional boolean with effective default `true`. Leave `payload.presentation.showDefault` absent or false so an omitted value adds no Settings row. If stored, show the `enabled` checkbox and use the effective value for the tree and its **Enable item** or **Disable item** action. |
| `id`, `name` | Title the fields `id` and `name`. The shared Value Control adds `(automatic)` to the read-only ID. Show the editable name next. |
| `periodicPairId` | Set the title `periodic pair` and widget `referenceSelector`. Use `payload.presentation.emptyChoiceLabel` with value `Choose periodic pair…`. Set the reference `targetLabel` to `periodic pair`, `scope` to `root`, `targetPath` to `["model", "mesh", "periodicPairs"]`, and `targetProperty` to `id`. The choices use the pair name and restrict eligibility to IDs in `/model/mesh/periodicPairIds`. Preserve an unavailable saved ID and expose its diagnostic. |
| `phaseVector` | Set the group title `phaseVector`, widget `quantityVector`, and `payload.widget.settings.componentLabels` to `["x-component", "y-component", "z-component"]`. Use widget `quantity` for each component. Leave `unitReadOnly` absent or false on both the vector and the component widget. Each axis exposes an expression textbox and a unit selector with accessible labels such as `x-component expression` and `x-component unit`. Offer the declared `rad/m` unit and preserve the stored array of quantity objects in axis order. |

In a disposable model written from the specification, give the mesh two eligible enabled pairs and one disabled pair. Open a Periodic condition with a saved phase vector and omitted `enabled`. Check the exact row order, labels, and control types. Verify the two enabled choices, the empty choice, and the absence of the disabled pair from eligible options. Check an unavailable saved ID separately. Change the referenced pair and one phase expression, using an equivalent expression such as `0 + 0` when the profile requires zero phase. Save and reopen. Verify only the stored `periodicPairId` and edited `phaseVector` component expression changed. The axis order, each unit, the stable condition ID, and the absence of `enabled` persist. Exercise **Disable item** and **Enable item** on that condition and verify the saved boolean and menu state agree after reopening.

### Field plot Settings

Show one **Quantity** selector for `/model/results/*/quantity`. Populate it in order with the active formulation's primary fields, its derived fields, supported pointwise variables in model order, and plottable material variables in declaration order. Exclude solver fields declared in `zeroFieldVariables` or marked zero in the active dimension. Include material variables only when the profile allows material plotting and the declaration permits the variable to be plotted. For each eligible symbol list the declared `real`, `imaginary`, and `magnitude` options in that order, labeled `Re(symbol)`, `Im(symbol)`, and `|symbol|`. After loading a checked sample, keep an eligible choice visible and disable it when that sample lacks the required values. A choice stores `{ type, component, part }` at the bound path. Hide the raw quantity object in the generic Settings table.

Bind the sole case-selection control, the shared **Data selection** widget, to the field recipe's `filters`. Use `runtime.resultDatasets` as the data source with `selectionMode` set to `fixed` and `showDefault` set to `true`. Match the table to the recipe ID. Show one sampled-value selector for each independent parameter of the checked field dataset. Store the raw values of the selected tuple. Preserve the recipe's `frequency.expression` and `frequency.unit` when the user changes the sample. Use the resolved default for display when filters are absent and keep absent values absent until the user applies an edit. Show an adjustment or selection error when the stored values cannot resolve to the exact requested case.

Before a completed result exists, show “Run a Study to make saved field data available.” Prefer the linked Physics frequency parameter's symbol and declared unit. The profile fallback is Hz for acoustics and EM2D, and GHz for EM3D. Convert display values from the checked case and keep the raw filter values unchanged. Thermal displays temperature in K and omits the frequency selector. ### Sweep plot Settings

For Study-backed `plot.sweep` recipes, bind `series` to the shared Repeatable Choice Table titled **Global variables to plot**. Set `choiceSource` to scope `root`, path `model`, `variables`, and `valueProperty` `symbol`. Set `choiceValueProperty` to `symbol` and `uniqueBy` to `column`. Use `{symbol} · {unit}` for the choice label and `{description}` for its description. Assign the symbol to `column` and `name`, and the selected definition's unit to `unit`. Use `id` as the generated ID property with a `series_{symbol}` template and use `left` as the new row's axis default. Preserve the IDs of unaffected rows on selection changes, removal, and reordering.

Show **Global variable** and **Actions** as the column headings and use **Add variable**, **Remove**, and the shared ordering controls. Exclude symbols already selected by another row. Disable removal at the required minimum and show a reason when no unused symbol is available. Set `siblingMirrors` to map `tableColumns` to `column`. Keep that ordered stored list in sync with the rows on add, change, remove, and reorder. Hide the separate `tableColumns` editor for the Study-backed recipe. The table of displayed data can also include the resolved X and independent parameter columns. File-backed datasets interpret series and table keys as literal CSV column names. [Repeatable Choice Table contract](../../../../platform/ui/widgets/repeatable-choice-table/fullmeta-ui-repeatableChoiceTable-1.schema.json)

Bind each sweep dataset's `filters` to the shared **Data selection** control in `slice` mode, with `runtime.resultDatasets` as its source and the dataset ID as its table identity. Set `showDefault` to `true`. Bind `varyingColumnProperty` to `xColumn`, `unitProperty` to `xUnit`, and the fixed values to `filters`. Label the varying column **X axis**. Plot and Table use all sampled X values that match one exact saved value for every other resolved independent parameter. Display each fixed value in its declared unit and store its raw value. Applying a change updates both views from the same selected rows. Show a visible message when saved selections require adjustment. Opening a recipe or showing defaults leaves its saved X key, unit, and filters intact.

## Acceptance for widget bindings

Open each supported item and field variant in the Model Editor using a disposable model derived from the specification. Record its widget, canonical path, visible labels, initial values, and permitted actions. Edit a representative value, Save, reopen, and compare the serialized value. Check condition changes that reveal or hide fields, empty and populated collections, unavailable reference choices, and the graphics response to selection. Record an isolated failure case for each relevant validation and verify the repair restores the expected state. [Function coverage](function-contract-coverage-method.md)

Exercise Quantity in a formulation with both a dimension-specific zero field and a plottable derived field. Include a pointwise definition, a plottable material variable, and an otherwise eligible component whose values are missing from the checked artifact. Verify the exact order, zero-field exclusion, disabled choice, and stored quantity object. With a checked mesh, change Edges while Mesh is off, visit a field and both the Plot and Table views, return to Geometry, and turn Mesh on. Verify that the retained Edges preference controls the wires and the active row retains its Settings throughout layer changes.
