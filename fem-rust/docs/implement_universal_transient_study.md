# Universal transient Study: implementation plan and status

## Status and objective

This document records the design and implementation of one scenario-neutral **Transient Study** for all eight existing scenarios: acoustic, electromagnetic, elastic and thermal, each in 2D and 3D. Users specify an initial state, time interval, time-dependent sources and boundaries, and desired output times. Materials may be declared as expressions of spatial coordinates and time, subject to each scenario's declared constitutive law. The model JSON holds user values; scenario JSON declares physical meaning, field components, units, admissible studies, constitutive terms and supported options. The shared FEM runtime interprets those declarations without a profile-ID switch in the assembler or time integrator.

The shared sparse backward-Euler runner, scenario-declared mixed state forms, time/space material and source sampling, initial-state projection, boundary routing, fixed zero-phase periodic constraints, Study preparation, coordinator, snapshot publication and FEM-owned time selection are implemented. All eight scenario packages advertise transient preparation and declare their forms, boundary laws, selections, outputs and material contracts. The exact equations, supported cases, test evidence and numerical limits are maintained in [the transient contract](transient_study_contract.md).

Thermal uses the selected law C(x,t) dT/dt and requires a positive volumetric heat capacity. Acoustic and electromagnetic forms declare conserved-product derivatives; elasticity advances displacement and velocity. Omitted initial fields use the declared zero default, and declared initial values and prescribed boundaries are checked for compatibility. Synthetic native release-coordinator runs cover all scenario forms, including space/time-varying materials and sources and time-varying prescribed boundaries. The older deployed Store host and visible editor workflow still need direct compatibility verification.

Synthetic tests cover nonzero and overlapping sources, selected discontinuous materials, declared prescribed boundaries, zero-phase periodic maps, parameter sweeps including remeshing, exact sample identities and mixed harmonic/transient validation. The transient coordinator evaluates global/probe values at requested output times and publishes a checked time-history CSV; field snapshots may be disabled independently. Time refinement is checked on all ten declared forms. Structured and perturbed-interior simplex mesh-refinement studies cover thermal and acoustic in both dimensions, elastic plane stress, plane strain and 3D, and EM Ez, Hz and 3D edge fields. The EM2D cases compare each mesh against a finer solution at the same time step to separate spatial error from backward-Euler time error; the irregular cases use nearest fine-grid reference nodes because their interior vertices differ. Scenario-assembled energy balances cover all declared forms, and thermal integrated-flux balance is tested in both dimensions. Operation-level cancellation/restart, visible editor acceptance and compatibility with the older deployed host remain outstanding. Frequency-domain dispersion is not an instantaneous time-domain material law; unsupported causal models must be rejected, not reinterpreted. Nonzero legacy electromagnetic scalar Neumann data likewise lacks a declared transient law.

The target is a common study capability, not a promise that unrelated PDEs have the same unknowns, element spaces, boundary equations or one universally appropriate numerical method. Existing stationary and harmonic behavior, scenario capabilities, sparse master matrices and saved projects remain on their existing routes. Supported transient physics and remaining limits are stated in the scenario packages and [the transient contract](transient_study_contract.md).

## Implemented architecture and current numerical constraints

The implementation keeps `src/assembler.rs` scenario-neutral and sparse. Generic element assembly, mixed field blocks, time derivative declarations and sparse constraint maps produce the effective backward-Euler matrix; the eight scenario packages supply the forms and field/space details. Global matrices are not densified. The topology-derived sparsity pattern can be reused while mesh, DOF layout and constraints are unchanged. Numeric matrix values and factorization are recomputed as required for time-dependent coefficients and changing steps.

`src/transient.rs`, `study_prepare.rs`, `scenario_runtime.rs` and `coordinator.rs` implement expression sampling, mixed state preparation, the solver route and time-indexed outputs. The model reserves dimensioned `t`; prepared cases resolve sweeps independently. Thermal packages add a required positive volumetric heat capacity only for transient studies. The result format includes physical time, case and sample identity. Detailed equations, boundaries, snapshots, validation and test limits are in [the transient contract](transient_study_contract.md).

The implementation supports nodal Lagrange fields and oriented tetrahedral edge fields for the declared forms. It does not claim arbitrary mixed element families, state-dependent nonlinear materials, general causal dispersion, nonzero transient EM scalar Neumann laws, or arbitrary order-two face-mode periodic transformations. The shared sparse direct solver refactorizes the numeric matrix each step; this is correct for changing operators but can be costly. Pattern caching does not imply numeric-factorization reuse.

The original implementation checklist follows as a design reference. Its requirements have been mapped into the shared contracts and tests; acceptance items still outstanding are called out in the status section above and in the [contract's verification summary](transient_study_contract.md#verification-status-and-remaining-acceptance-work).

## Implemented study and project contract

1. The `transient` Study uses SI seconds, finite ordered start/end times, maximum step/step-count limits and requested output times. Backward Euler shortens a step to land on a requested output time; outputs are sampled at those requested times without interpolation.
2. Each package advertises supported Study types independently of its default and declares `transientPlan` by profile. Existing stationary/harmonic Study defaults remain intact, and the selected Study controls preparation and expression scope.
3. Transient tree creation, typed Study settings, validation, coordinator progress and FEM-owned result selection use the application schema and operation lifecycle. Drafts and progress remain outside persisted model values. Older Store host compatibility is a remaining visible acceptance check.
4. Scenario JSON declares state fields, units, initial-field defaults and supported finite-element spaces. Initial expressions are sampled/projected into the declared space; compatibility with prescribed values and supported initial rates is checked before advancing.
5. Dimensioned `t` is reserved. Per-case parameter sweeps resolve independently, and study preparation validates expression symbols, units and dimensions using the selected Study's scope. Frequency-domain material/source expressions are rejected for transient input rather than reinterpreted as time-domain data.

## Physical models and constitutive time derivatives

The scenario packages declare the independent state, PDE terms, units, source signs, 2D reduction, material variations and boundary semantics. The distinctions below are implemented in JSON and described in detail, with weak forms and matrices, in [the transient contract](transient_study_contract.md):

| Scenarios | Implemented state and PDE | Material derivative law and limits |
| --- | --- | --- |
| Acoustic 2D, 3D | Pressure and velocity state fields; conservation equations for pressure storage and momentum with declared normal-velocity and impedance boundary laws. The 2D reduction has two in-plane velocity components and zero out-of-plane velocity. | `b=1/(rho c^2)` and `rho v` use conserved-product derivatives. Coefficients may vary in position and time. Harmonic loss has no inferred causal transient law. |
| EM 2D, 3D | First-order E/H fields, with z-invariant `Ez` and `Hz` reductions in 2D and oriented tetrahedral edge spaces in 3D. Declared curl/source and tangential boundary operations define coupling. | `epsilon E` and `mu H` use conserved-product derivatives; conductivity is instantaneous. Tensor/nonreciprocal constitutive models, causal dispersion and nonzero scalar Neumann transient data are outside the current declarations. |
| Elastic 2D, 3D | Displacement/velocity state; plane stress and plane strain in 2D and three-component displacement in 3D. Declared body-force, traction, prescribed displacement and impedance boundaries. | Density-weighted momentum uses a conserved-product derivative; elasticity uses instantaneous isotropic stress. Harmonic density loss is not a transient damping law. |
| Thermal 2D, 3D | Temperature state with conductivity, Domain Source and required positive volumetric heat capacity only when a transient Study is used. | The selected law is `C(x,t) partial_t T`, not `partial_t(C T)`. Conductivity and capacity may vary in space and time. Existing stationary studies do not require capacity. |

All current transient material laws support prescribed parameter, spatial and temporal dependence where declared by the package. State-dependent nonlinear constitutive laws are not declared. Time-varying coefficients describe a prescribed time-varying medium and are **not** a generic conversion from frequency dispersion. Dispersive material and impedance laws require explicit causal convolution or auxiliary-state contracts; unsupported frequency-only expressions are rejected.

## Scenario-neutral weak forms and discretization

1. Each scenario JSON declares field IDs, component shapes and units, element family/order, trial and test operators, coupled blocks, coefficients, load terms, derivative law, and recovery/output mapping. `timeDerivative` distinguishes a state derivative, conserved-product derivative and algebraic/spatial term.
2. Shared kernels assemble the declared sparse operators over scalar nodal, vector nodal and oriented tetrahedral edge bases. Cross-field blocks use the global block layout and each field's own basis. Adding a JSON-only scenario is supported when its mathematical operations are already in this vocabulary; new mathematics still requires a shared extension.
3. The JSON boundary contract routes prescribed values, traces/fluxes, traction, normal velocity, impedance and fixed periodic identification through shared operations. Time-varying prescribed inputs are sampled at the step time; displacement and initial-rate compatibility is checked where required. Unsupported or inconsistent boundary data fail with diagnostics.
4. Domain Sources use scenario-declared units, target rows and signs. Multiple sources add on overlapping selections; no source contributes zero and skips expression compilation/evaluation. Space/time expressions are sampled at physical integration points and stages.
5. All eight scenario JSON files declare transient behavior while retaining their harmonic or stationary contracts and defaults. The assembler and coordinator choose behavior from the Study route and package data, not a hard-coded scenario switch.

## Time stepping and sparse performance

- Backward Euler is the implemented first-order implicit method. The matrix and RHS use the declared state or conserved-product derivative law. The implementation does not claim accuracy from solver success alone; backward Euler damps waves and convergence remains case-dependent.
- Mesh/field topology, DOF numbering, element order and constraint graph determine the sparse pattern. Cached assembly locations are reused while those inputs match. A sweep that remeshes or changes its field/constraint graph constructs fresh patterns and maps.
- Coefficient-dependent operator values are sampled and assembled at the required time stage. Time-varying material or boundary operators can change matrix values while the sparse graph stays fixed; RHS-only sources do not change the matrix. The sparse effective system is rebuilt without densifying the master matrix.
- Sparse pattern and symbolic data may be reused when structure and backend settings match. Numeric factorization is currently repeated at each time step; no numeric-factor reuse is claimed. A future reuse is valid only when the entire constrained matrix, step size, stage and backend settings are unchanged.
- The transient runner uses a sparse direct solver compatible with its assembled matrix; it does not infer symmetry from sparsity alone. Non-finite inputs, singular solves and incompatible constraints are errors. Wider baseline timing and cache-on/off benchmarking remain acceptance work.

## Outputs, validation and compatibility

- `fullmeta-transient-field/1` snapshots carry exact physical time, Study/case/sample identity, mesh association and declared fields. The coordinator publishes a time-history CSV for global values and probes without requiring a field file for every step; requested output times are sampled directly.
- Run records remain identified by model and Study IDs. Sweep cases and times are explicit in outputs and result filtering; changing the Study fingerprint invalidates stale results. Transient runs use the shared operation lifecycle and report progress and completion.
- Study preparation validates the time grid, required thermal capacity, initial fields, selections, expression symbols/units/dimensions and declared boundary compatibility. Runtime sampling rejects non-finite/out-of-bound coefficients and incompatible values at their actual point and time. Disabled project features retain their existing semantics.
- Existing project loading and stationary/harmonic routes remain covered by the Rust suite and release probes. The FEM-local native bundle and browser WASM have passed their checks; visible interactive behavior in the older deployed Store host remains unverified. The release bundle built here was not installed into the user's Store app.
